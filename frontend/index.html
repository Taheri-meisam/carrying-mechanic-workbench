What the workbench does, and what it does not

Each game passes through six parts in order. The output is a record, not a score.

  1. Carrying mechanic. The rule element without which this is a different game. Everything below is judged against it.
  2. Gates. G1 a rule system with a defined end state. G2 a bounded session without unrepresentable equipment. G3 the carrying mechanic is kept or transformed under at least one interface class: S screen-only touch, M motion or sensor, L location or co-located.
  3. Route. R1 needs an opponent and produces a winner. R2 closes without a winner and can be played alone. R3 has a making layer where the constructed object decides performance. Decided by test, not keywords: remove the second player; is there a build phase.
  4. Dimensions, 0–2 with a written descriptor. MC rule decomposability. LOM the counterfactual: remove the educational content, does the same strategy still win. AGE which developmental competence the mechanic depends on and whether it carries a native scaling parameter. CT-a legibility from the rules alone; CT-b and CT-c recorded, not scored.
  5. Ledger. For each rule and material element: kept, transformed, substituted, removed, added under the target class. The S column of the DIG profile is read off this table.
  6. Distinctiveness. D0 rule-for-rule counterpart found, D1 family counterpart with a differing rule, D2 none found. The model does not assign a level (instrument v0.5): it cannot browse, so it gives a search hypothesis only. A separate, logged retrieval step finds candidates and retains a counterpart only if it has a resolvable identifier (Ludii, BoardGameGeek, Wikipedia). The coder reviews the log, confirms or overrides the counterpart, assigns the level and sets verified.

Eligibility as a worked example requires MC ≥ 1, LOM ≥ 1, DIG ≥ transformed under the target class, CT-a ≥ 1, and all sections reviewed by a coder. Nothing compensates for a failed minimum.

Division of labour. The model reads consistently, quotes the source, drafts the ledger and names ambiguities. The human decides. Scores used in a paper are the reviewed ones; the raw extraction is kept alongside so agreement can be measured on a gold set.

Records are stored in the shared pool for everyone in the organisation who opens this page. The pool is organisation-internal and cannot be shared publicly.
